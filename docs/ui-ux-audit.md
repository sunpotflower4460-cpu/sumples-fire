# UI/UX Audit — Fire Task

## 調査概要

**アプリ**: Fire Task  
**スタック**: React 19 / TypeScript / Vite / Pure CSS / Web Audio API / localStorage  
**UIライブラリ**: なし（カスタムCSS）  
**画面構成**: 3タブ（今日 / 炭 / 使い方）＋ モーダルシート（タスク追加）

---

## 主要画面一覧

| 画面 | 説明 |
|------|------|
| 今日（today） | 未燃焼タスク一覧・マトリクスサマリー・炭ポイント・今日の火種カード |
| 炭（ash） | 燃焼済みタスク一覧・合計ポイント |
| 使い方（info） | アプリ説明・音設定・保存状況 |
| タスク追加シート | ボトムシートモーダル（緊急度・重要度・重さ選択） |

## 主要ユーザーフロー

1. **初回起動** → ヒーローセクションを見る → 「最初のタスクを書く」ボタンを押す
2. **タスク追加** → ＋ボタン or FAB → 名前入力 → 緊急度・重要度・重さ選択 → 保存
3. **タスク燃焼（Fire）** → 今日の火種カードまたはリストの「完了してFire」ボタン
4. **炭履歴確認** → 炭タブ → 燃焼済みタスク一覧
5. **設定確認** → 使い方タブ → 音ON/OFF・保存件数確認

---

## UI上の課題（優先度つき）

### P1: 日常的な使いにくさ

| # | 問題 | 対象ファイル | 影響 |
|---|------|------------|------|
| 1 | トースト通知の表示時間が 2400ms と短め。日本語テキストを読むのに余裕がない場合がある | `useFireSeeds.ts` | 通知を読み損ねる可能性 |

### P2: 品質向上・磨き込み

| # | 問題 | 対象ファイル | 影響 |
|---|------|------------|------|
| 2 | フィルター「燃焼済み」「すべて」を今日タブで選択しても `activeTasks` の計算で burned タスクが除外されるため実質空になる（設計上の矛盾） | `App.tsx` | ユーザーが「バグ？」と感じる可能性（今回はスコープ外） |

## 対応済み（過去指摘）

- モーダルのフォーカストラップを実装（`useFocusTrap` + `App.tsx`）
- フィルターボタンの `aria-pressed` と `role="group"` を実装（`FireFilters.tsx`）
- `font-weight: 1000` を `900` に修正（`rewardEffects.css`）
- ランクプログレスバーに `role="progressbar"` / `aria-valuenow` を追加（`FireStats.tsx`）
- `<details>` の `summary` に展開インジケーターを追加（`styles.css`）
- タブ切り替え時の `document.title` 更新を実装（`App.tsx`）
- `idea-button` のホバーフィードバックを追加（`styles.css`）
- `matrix-badge` / `stage-row` の `title` 属性依存を解消（`FireCard.tsx`）

---

## 影響が大きい改善ポイント

1. **通知可読性の改善**（P1）— トースト表示時間を見直して読み損ねを減らす
2. **フィルター仕様の整理**（P2）— UI上の選択肢と実際の挙動を一致させる

## 既存実装の良い点

- `aria-modal`, `aria-labelledby`, `aria-live`, `aria-hidden`, `aria-label` が多くの箇所で既に使われている
- フォーカスリング（`:focus-visible`）が全体に定義されている
- Escape キーでのモーダル閉鎖が実装済み
- Safe-area インセット対応が済んでいる
- prefers-reduced-motion のメディアクエリが適切に設定されている
- モバイル・デスクトップ両対応のレスポンシブ設計
